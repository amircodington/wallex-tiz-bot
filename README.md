# TIZ: ربات معاملاتی والکس (چالش والکس، هکاتون استارکوچ)

ربات خودکار اسپات روی صرافی والکس: داده‌ی بازار را می‌گیرد، با یک قاعده‌ی مشخص فرصت پیدا می‌کند، یک داور AI هر بازار را با دلیل تأیید یا رد می‌کند، دروازه‌ی ریسک سخت (بیرون از AI) حجم و ضرر را محدود می‌کند، سفارش لیمیت می‌گذارد و هر تصمیم را در لاگ JSON ثبت می‌کند. بدون دخالت دستی.

## معماری

یک پروسه‌ی پایتون (`asyncio`)، سه فایل:

| فایل | کار |
|---|---|
| `src/tiz/wallex.py` | آداپتور والکس: REST (ثبت/لغو/وضعیت سفارش، موجودی، کارمزد) با هدر `x-api-key`، و سوکت عمق بازار (`wss://api.wallex.ir/ws`) |
| `src/tiz/bot.py` | فید بایننس، استراتژی، داور AI، دروازه‌ی ریسک، اجرای سفارش، ژورنال SQLite و لاگ تصمیم |
| `src/tiz/backtest.py` | اجرای **همان کلاس Bot** روی تاریخچه‌ی ۱ دقیقه‌ای والکس و بایننس |

```
Binance <COIN>USDT ─┐                         ┌─ AI judge (هر ۵ دقیقه، Claude): approve/reject + دلیل + اطمینان
Wallex USDTTMN ─────┼─> fair, premium, baseline ─> سیگنال ─> دروازه‌ی ریسک ─> سفارش LIMIT ─> پیگیری فیل
Wallex <COIN>TMN ───┘                                                   └─> decisions.jsonl + journal.db + تلگرام
```

## منطق استراتژی: بازگشت پریمیوم (premium mean reversion)

- قیمت منصفانه‌ی هر کوین به تومان: `fair = Binance <COIN>USDT mid × Wallex USDTTMN mid`.
- هر بازار تومانی والکس با یک «پریمیوم» نسبت به fair معامله می‌شود که آهسته جابه‌جا می‌شود. میانگین متحرک نمایی ۳۰ دقیقه‌ای آن را `baseline` می‌گیریم و `baseline_fair = fair × (1 + baseline)`.
- **خرید:** سفارش لیمیت در `baseline_fair × (1 − ENTRY_EDGE)`. وقتی فروشنده‌ای در دفتر کم‌عمق والکس قیمت را موقتاً پایین می‌کشد، سفارش ما پر می‌شود. این یک شکاف نقدشوندگی است، نه پیش‌بینی جهت بازار؛ قیمت جهانی مرجع است.
- **فروش:** لیمیت در `baseline_fair` (هرگز زیر نقطه‌ی سربه‌سر + کارمزدها + `MIN_PROFIT`).
- **خروج اجباری:** حد ضرر ۱.۵٪، حداکثر نگه‌داری ۱ ساعت، و بستن همه‌چیز در پایان چالش، با فروش روی بهترین bid.
- سفارش‌ها هر ۲ دقیقه با قیمت تازه جایگزین می‌شوند.
- بازارها: BTC، ETH، XRP، DOGE، SOL و PEPE به تومان. هیچ‌کدام در فهرست بازارهای غیرمجاز حساب اعتباری (`config/disallowed_markets.txt`) نیستند و ربات اگر نماد غیرمجازی تنظیم شود اجرا نمی‌شود.

## نقش AI

هر ۵ دقیقه یک مدل زبانی (پیش‌فرض: `claude -p --model haiku`، قابل تعویض با `AI_CMD`) برای هر بازار این‌ها را می‌خواند: پریمیوم فعلی و baseline، میانگین و انحراف معیار پریمیوم ۳۰ دقیقه، کمینه و بیشینه‌ی ۲ ساعت، تغییر ۱ ساعته و نوسان بایننس، اسپرد والکس، نتیجه‌ی معاملات اخیر همان بازار، افت روزانه و ساعت‌های باقی‌مانده. خروجی‌اش برای هر بازار `approve` یا `reject`، اطمینان ۰ تا ۱، و دلیل نوشته‌شده است.

- فقط بازارهای تأییدشده سفارش ورود می‌گیرند و ظرفیت آزاد (حداکثر ۳ پوزیشن) به ترتیب اطمینان AI تقسیم می‌شود.
- AI حجم، حد ضرر یا سقف‌ها را تعیین نمی‌کند و نمی‌تواند دورشان بزند.
- اگر AI جواب ندهد یا رأی‌اش بیش از ۱۵ دقیقه کهنه شود، همه‌ی بازارها رد حساب می‌شوند (fail closed). خروج‌ها به AI وابسته نیستند.
- هر دور داوری (کانتکست + رأی‌ها) و هر رد شدن با دلیلش در `decisions.jsonl` ثبت می‌شود.

## مدیریت سرمایه و ریسک (در کد، بیرون از AI)

| قاعده | مقدار پیش‌فرض | متغیر |
|---|---|---|
| حجم هر پوزیشن | ۲۰٪ ارزش حساب | `POS_FRAC` |
| حداکثر پوزیشن یا سفارش ورود هم‌زمان | ۳ (یعنی دست‌کم ۴۰٪ همیشه تومان) | `MAX_POS` |
| حد ضرر هر پوزیشن | ۱.۵٪ | `STOP_LOSS` |
| حداکثر نگه‌داری | ۱ ساعت | `MAX_HOLD` |
| توقف روزانه (به وقت تهران) | افت ۳٪ از ارزش اول روز، بدون ورود تا فردا | `DAILY_STOP` |
| فید کهنه | بیش از ۳۰ ثانیه: لغو سفارش و توقف آن بازار | `STALE` |
| پایان چالش | ورود ممنوع از ۳ ساعت قبل، بستن همه از ۱ ساعت قبل از `END_TS` (جمعه ۱ آبان، ۲۳:۵۰ تهران) | `ENTRY_CUTOFF`، `FLATTEN_BEFORE`، `END_TS` |
| یکپارچگی | موجودی هر ۱۵ ثانیه از صرافی خوانده می‌شود؛ بعد از ری‌استارت، کوین‌های موجود در بازارهای ربات «پوزیشن» حساب می‌شوند تا بسته شوند | |

**کارمزد:** API حساب (`/v1/account/fee`) برای بازارهای تومانی میکر ۰.۲۵٪ و تیکر ۰.۳٪ گزارش می‌کند، ولی طبق اعلام والکس اسپات کارمزد معاملاتی ندارد. ربات محتاطانه با عدد API شروع می‌کند (`ENTRY_EDGE=0.8%`) و اگر اولین فیل واقعی کارمزد صفر داشت، خودکار به `FEE=0` و `ENTRY_EDGE=0.5%` می‌رود و این را در لاگ ثبت می‌کند.

### تست سایه (Shadow)

`MODE=paper` همان کد را روی داده‌ی زنده اجرا می‌کند و سفارش را به صرافی نمی‌فرستد؛ فیل وقتی ثبت می‌شود که بهترین قیمت مقابل به سفارش برسد. نتایج در `results/shadow_decisions.jsonl` و `logs/shadow.log` است (اجرای اول از ۳۰ مهر، ساعت ۱۲:۱۳ تهران).

## اجرا و اجرای مجدد

```bash
uv sync
cp .env.example .env          # WALLEX_API_KEY (فقط مجوز معامله)، TELEGRAM_* اختیاری
uv run pytest -q              # ۷ تست: سود رفت‌وبرگشت، سقف حجم، حد ضرر و توقف روزانه، رد AI، فید کهنه، بستن پایان چالش
uv run python -m tiz.backtest fetch 3   # دانلود ۳ روز تاریخچه به data/
uv run python -m tiz.backtest           # بک‌تست → results/backtest.json
MODE=paper uv run python -m tiz.bot     # تست سایه روی بازار زنده
MODE=live  uv run python -m tiz.bot     # معامله‌ی واقعی
```

برای اجرای AI، Claude Code (`claude`) باید نصب و وارد شده باشد؛ هر CLI دیگری که پرامپت را از stdin بگیرد و JSON چاپ کند با `AI_CMD` جایگزین می‌شود.

## خروجی‌ها و ارزیابی

- `decisions.jsonl`: هر رکورد شامل `signal` (fair، baseline، bid/ask، پریمیوم)، `ai` (رأی، اطمینان، دلیل)، `risk` (حجم و درصد، حد ضرر، افت روزانه، ظرفیت)، `order` و `manual: false`. ردشده‌ها با `decision: skipped` و دلیل ثبت می‌شوند.
- `journal.db` (SQLite): جدول‌های `samples`، `orders`، `fills`، `trades` و `events`. مثال: `sqlite3 journal.db "select sym, count(*), sum(pnl_tmn) from trades group by sym"`.
- لاگ ترمینال هر ۵ دقیقه ارزش حساب، بازده نسبت به ۵ میلیون، بیشترین افت و پوزیشن‌ها را چاپ می‌کند.
